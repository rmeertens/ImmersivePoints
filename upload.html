Your files

Host your own pointcloud files and view them in virtual reality using ImmersivePoints.

How to host your own pointcloud files

To view your pointcloud in VR, you need to host your binary file on a web server and pass its URL to the viewer. Here's how:

1 Prepare your pointcloud file

Export your pointcloud as a binary file in one of the supported formats (see file format specifications below).

Large file? Compress it with Cloudini to make it several times smaller, so it downloads faster in the headset.

2 Host your file

ImmersivePoints does not host files: it is not possible to upload your data to the ImmersivePoints server or its storage bucket. Put your binary file on any web hosting service you control that supports CORS. Some options include:

  • GitHub Pages - Free hosting for static files. Simply add your file to a repository and enable GitHub Pages.
  • Amazon S3 - Create a public bucket in your own AWS account and configure CORS for it.
  • Google Cloud Storage - Use a bucket in your own account with public access or CORS configured.
  • Your own web server - Ensure CORS headers are set to allow requests from immersivepoints.meertens.dev

Important: The hosting server must allow cross-origin requests (CORS) from immersivepoints.meertens.dev for the viewer to load your file.

3 View in VR

Enter your hosted file URL below and we'll generate the viewer link for you:

Put {i} (or zero-padded {i:04}) in the file URL where the frame number goes, e.g. https://example.com/scan_{i:04}.xyzi.

Compress or decompress with Cloudini

Cloudini is an open-source point cloud compression format, also used for ROS bags and MCAP files. The viewer reads Cloudini files (.cldn) directly. Use the tools below to convert between ImmersivePoints files and Cloudini. Everything runs in your browser; your files are not uploaded anywhere.

Compress to Cloudini

Convert an ImmersivePoints file (.xyz, .xyzi or .xyzrgb, big-endian float32) to a .cldn file.

Quantisation step in your data's units: positions are decoded within half of this value. With metres, 0.001 is 1 mm.

Decompress from Cloudini

Convert a .cldn file to an ImmersivePoints file. Files made with the compressor above come back in their original format. Other Cloudini clouds, such as ones from a ROS bag, are converted to XYZRGB with the same colours the viewer shows.

File format specifications

All binary files must be in float32 format. ImmersivePoints supports two raw formats, plus compressed Cloudini files:

Coordinate system

Give all positions in a right-handed frame with X forward, Y left and Z up. This is the ROS convention (REP 103) and the vehicle frame most lidar datasets use, so a cloud straight from a sensor shows up the right way round with no conversion.

AxisDirectionAxes helper color
XForwardRed
YLeftGreen
ZUpBlue

Box sizes and rotations, line end points and object poses use the same axes, so a vehicle's heading is its rotation around Z. The viewer starts behind the origin, looking along +X. Add &showAxes=true to check your data against the axes.

Do not swap columns to make Y point up: swapping two axes mirrors the scene. Files made for the viewer's older convention (three.js axes: X right, Y up, Z toward the viewer) can still be shown as stored with &axes=threejs, or "axes": "threejs" in a JSON config.

XYZI Format 4 values per point

Position with hue-based coloring.

Field Type Description
Xfloat32Position forwards
Yfloat32Position upwards
Zfloat32Position left
Huefloat32Color hue (0.0 – 1.0)
The hue value follows the HSL color specification. Saturation and lightness are fixed at 1.0.

XYZRGB Format 6 values per point

Position with full RGB color control.

Field Type Description
Xfloat32Position forwards
Yfloat32Position upwards
Zfloat32Position left
Redfloat32Red channel (0.0 – 1.0)
Greenfloat32Green channel (0.0 – 1.0)
Bluefloat32Blue channel (0.0 – 1.0)

Cloudini Compressed

A Cloudini file (.cldn) holds one compressed point cloud and is typically several times smaller than the raw file. Make one with the compressor above, with the Cloudini tools (for example pcd_to_cloudini_converter or the Cloudini Python encoder), or take the compressed_data of a ROS point_cloud_interfaces/CompressedPointCloud2 message. The viewer recognises Cloudini data automatically from its CLOUDINI_V header and reads every version up to 6.

Field Type Used for
x, y, zany numeric typePosition (required). Points with a NaN or infinite coordinate are skipped.
huefloat32Color hue (0.0 – 1.0), as in XYZI
rgb / rgbauint32 or float32Packed 0x00RRGGBB color (ROS/PCL convention)
r, g, buint8, uint16 or floatSeparate color channels
intensityany numeric typeColored from blue (low) to red (high)
Colors use the first match in this order. With none of these fields, points are colored by height (Z). Other fields are ignored. Coordinates use the X forward, Y left, Z up convention, so clouds from ROS show up the right way round.

Advanced: URL Parameters

The viewer supports several URL parameters for different use cases:

Simple file URL Recommended

Pass a URL to your hosted binary file. The file extension determines the format.

oculus.html?url=https://example.com/mycloud.xyzi

Use .xyzi, .xyzrgb or .cldn file extension to auto-detect format, or add &mode=xyzi, xyzrgb or cloudini for other file names. URLs with their own query string, such as presigned links, can be pasted as they are: put url= last, or after it only the viewer options mode, showAxes and autoRotate. Encoding the URL with encodeURIComponent also works. The older name= parameter works the same way.

Sequences Animated

Play a series of point clouds over time, such as one lidar sweep per frame. Export one file per frame with the frame number in its name, then put {i} where the number goes. Use {i:04} for zero-padded numbers like 0007.

oculus.html?url=https://example.com/scan_{i:04}.xyzi&frames=0-199&fps=10

frames is an inclusive range (0-199) or a count starting at 0 (200). fps defaults to 10.

To add boxes and lines per frame, or a static map that stays visible, use a JSON config with a sequence entry. Pass it as jsonb64, or host the JSON file next to your frames and pass its URL with config=, which keeps long sequences out of the link:

oculus.html?config=https://example.com/drive.json
{
  "points": [ { "source": "url", "url": "https://example.com/map.xyzrgb", "type": "XYZRGB" } ],
  "sequence": {
    "points": { "url": "https://example.com/scan_{i:04}.xyzi", "type": "XYZI" },
    "bboxes": { "url": "https://example.com/boxes_{i:04}.bbox" },
    "start": 0,
    "count": 200
  },
  "fps": 10,
  "loop": true
}

If your files aren't numbered, list them instead. Every frame uses the same fields as a static scene, and an optional label (such as a timestamp) is shown next to the frame number:

{
  "frames": [
    { "label": "12:00:00.0", "points": [ { "source": "url", "url": "https://example.com/a.xyzi", "type": "XYZI" } ] },
    { "label": "12:00:00.1", "points": [ { "source": "url", "url": "https://example.com/b.xyzi", "type": "XYZI" } ] }
  ],
  "fps": 10
}

Exporting frames from Python:

for i, scan in enumerate(scans):   # each scan: float32 array with 4 columns (x, y, z, hue)
    scan.astype('>f4').tofile(f'scan_{i:04d}.xyzi')

Controls: on desktop, use the playback bar, Space (play/pause) and the Left/Right arrow keys (step). In VR, A or X plays and pauses, B steps forward and Y steps back. Frames load in the background, starting with the first one. Every loaded frame stays in memory, so keep the total number of points across all frames within what your headset can handle.

Inline Base64 Points No hosting required

Embed small pointclouds directly in the URL as base64-encoded data. Great for sharing without hosting.

oculus.html?base64=YOUR_BASE64_ENCODED_DATA

Encode your binary float32 data as base64. Works for XYZI format.

JSON Configuration Advanced

For complex scenes with multiple pointclouds, lines, bounding boxes, and 3D objects, use a base64-encoded JSON configuration.

oculus.html?jsonb64=BASE64_ENCODED_JSON

Example JSON structure:

{
  "points": [
    {
      "source": "url",
      "url": "https://example.com/cloud1.xyzi",
      "type": "XYZI",
      "pointSize": 0.04
    },
    {
      "source": "base64",
      "base64": "BASE64_DATA_HERE",
      "type": "XYZRGB"
    }
  ],
  "lines": [
    {
      "source": "url",
      "url": "https://example.com/lines.bin"
    }
  ],
  "bboxes": [
    {
      "source": "url",
      "url": "https://example.com/boxes.bbox"
    }
  ],
  "objects": [
    {
      "source": "url",
      "url": "https://example.com/model.glb",
      "position": [1.0, 2.0, 3.0],
      "rotation": [0.0, 0.0, 0.0],
      "scale": [1.0, 1.0, 1.0]
    }
  ]
}

Object position, rotation (radians, around X, Y and Z) and scale use the data axes. glTF models are made Y up with their front facing +Z; the viewer stands them up along Z with their front along +X. Add "axes": "threejs" to show a whole config as stored.
